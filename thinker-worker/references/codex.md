# Codex routing

Use an explicit native `spawn_agent` model and `reasoning_effort`, both within the role's policy in `routes.json` (`harnesses.codex.roles`). As shipped: `worker` on `gpt-6-sol`, `gpt-5.6-sol`, or `gpt-5.6-terra` (Terra is being phased out) at `low`/`medium`/`high`/`xhigh`; `leaf` on `gpt-6-luna` at `low`/`medium`; `independent-review` and `ideation` on `gpt-6-astra` at `medium`/`high`/`xhigh`. Every role needs an explicit `reasoning_effort` from its list; an omitted value, or one outside it (there is no `max` or `ultra`), is denied. Review and ideation carry `TW-Role: independent-review` or `TW-Role: ideation` and a bounded authorization in the brief. Optional Luna is only a short, objectively checkable leaf with `TW-Role: leaf`; start with low effort. Prefer a deterministic command for exact extraction when it suffices. No Luna physics judgment, architecture, adversarial review, or acceptance.

Pass `fork_turns: "none"` or a bounded positive history count whenever using explicit model/effort. Omitted or `all` is rejected while this mode is active, as is an `agent_type` other than `default`. The model/effort override requires `fork_turns` other than full history in the current desktop tool. Keep `message` first line as the role declaration; put the assignment below it. A manual model/effort pin takes precedence over this mode: report incompatibility instead of silently changing it or deactivating the mode.

Activation is exact-session only. Resolve the absolute installed skill directory from the Codex skill catalog, and use its `scripts/tw.py` with the actual `CODEX_THREAD_ID` for this task. The command is `python "<skill-dir>/scripts/tw.py" activate --harness codex --session "<actual CODEX_THREAD_ID>"` (optionally `--store-bodies`); replace the session placeholder with the task's real ID. `status` reports requested activation; it cannot establish trust or interception. Inspect `/hooks` to review and trust the exact owned hook definition. A changed definition needs renewed trust. Record a live hook receipt and the first actual child turn's model/effort metadata separately. A CLI hook result does not qualify an already-running desktop task; probe that surface independently. New/forked session IDs start inactive. Same-session resume retains activation until `deactivate`.

When the owned PreToolUse hook is loaded and trusted, its matcher covers legacy `spawn_agent`/`Agent` and the MultiAgentV2 hook name `collaborationspawn_agent`. The latter is the flattened hook payload name; the displayed `collaboration.spawn_agent` tool notation is not the matcher string. The guard covers fresh calls only where Codex invokes PreToolUse. It does not cover continuation via `followup_task`, cross-task messages, arbitrary shell/provider calls, or provider substitutions. Before resuming a child, verify its effective model/effort and assignment from runtime metadata; do not rely on a continuation prompt. A direct script invocation or hook listing alone does not prove live interception. An allowed guard result has no permission override.

On MultiAgentV2, Codex presents the `message` to PreToolUse as ciphertext. The hook cannot inspect its role declaration, review authorization, scope, or task content. For `collaborationspawn_agent`, it derives the route from the visible explicit model (Sol or Terra worker, Luna leaf, Astra review or ideation) and checks model, effort, fork mode, and agent type. An Astra dispatch's receipt records role `null`, because the ciphertext cannot say whether it is review or ideation. The coordinator must read the actual brief before dispatch and enforce role/scope procedurally. Receipts mark brief checks unavailable on this path and record `header: null`, and the dispatch gets no router decision (the `task_name` join is not built). Plaintext paths record the validated routing header (never the brief body); receipts are request evidence, not semantic validation or proof of effective child model.

Plaintext Codex dispatches get the same `route` row, modes, `TW-Override:` rule, and error handling as Claude (see [Claude routing](claude.md)), with two differences: `active` behaves as `advisory` (the denial names `reasoning_effort=<tier>`), and there are no `race` or `cost` rows. `tw.py outcome`, `route`, and `promote` take `--harness codex`.

Official contract: [Codex hooks](https://learn.chatgpt.com/docs/hooks), [subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents).
