# Codex routing

Use an explicit native `spawn_agent` model and `reasoning_effort`, both within the role's policy in `routes.json` (`harnesses.codex.roles`). As shipped: `worker` on `gpt-6-sol`, `gpt-5.6-sol`, or `gpt-5.6-terra` (Terra is being phased out) at `low`/`medium`/`high`/`xhigh`; `leaf` on `gpt-6-luna` at `low`/`medium`; `independent-review` and `ideation` on `gpt-6-astra` at `medium`/`high`/`xhigh`. Every role needs an explicit `reasoning_effort` from its list; an omitted value, or one outside it (there is no `max` or `ultra`), is denied. Review and ideation carry `TW-Role: independent-review` or `TW-Role: ideation` and a bounded authorization in the brief. Optional Luna is only a short, objectively checkable leaf with `TW-Role: leaf`; start with low effort. Prefer a deterministic command for exact extraction when it suffices. No Luna physics judgment, architecture, adversarial review, or acceptance.

Pass `fork_turns: "none"` or a bounded positive history count whenever using explicit model/effort. Omitted or `all` is rejected while this mode is active, as is an `agent_type` other than `default`. The model/effort override requires `fork_turns` other than full history in the current desktop tool. Keep `message` first line as the role declaration; put the assignment below it. A manual model/effort pin takes precedence over this mode: report incompatibility instead of silently changing it or deactivating the mode.

Activation is exact-session only. Resolve the absolute installed skill directory from the Codex skill catalog, and use its `scripts/tw.py` with the actual `CODEX_THREAD_ID` for this task. The command is `python "<skill-dir>/scripts/tw.py" activate --harness codex --session "<actual CODEX_THREAD_ID>"` (optionally `--store-bodies`); replace the session placeholder with the task's real ID. `status` reports requested activation; it cannot establish trust or interception. `activate` and `status` end with the effective tier priors line. Pick the `reasoning_effort` from the priors `activate` prints for the brief's `TW-Class`; deviate by judgment when the brief is clearly easier or harder than its class; physics or convention judgment never below `medium`; `high` or `xhigh` for adversarial reasoning. The priors, the user override file, and the per-dispatch `override` error row are as in [Claude routing](claude.md); route rows record `prior_tier`, but Codex gets no prior reminder (its handling of `additionalContext` without a decision is unverified). Inspect `/hooks` to review and trust the exact owned hook definition. A changed definition needs renewed trust. Record a live hook receipt and the first actual child turn's model/effort metadata separately. A CLI hook result does not qualify an already-running desktop task; probe that surface independently. New/forked session IDs start inactive. Same-session resume retains activation until `deactivate`.

When the owned PreToolUse hook is loaded and trusted, its matcher covers legacy `spawn_agent`/`Agent` and the MultiAgentV2 hook name `collaborationspawn_agent`. The latter is the flattened hook payload name; the displayed `collaboration.spawn_agent` tool notation is not the matcher string. The guard covers fresh calls only where Codex invokes PreToolUse. It does not cover continuation via `followup_task`, cross-task messages, arbitrary shell/provider calls, or provider substitutions. Before resuming a child, verify its effective model/effort and assignment from runtime metadata; do not rely on a continuation prompt. A direct script invocation or hook listing alone does not prove live interception. An allowed guard result has no permission override.

On MultiAgentV2, Codex presents the `message` to PreToolUse as ciphertext. The hook cannot inspect its role declaration, review authorization, scope, or task content. For `collaborationspawn_agent`, it derives the route from the visible explicit model (Sol or Terra worker, Luna leaf, Astra review or ideation) and checks model, effort, fork mode, and agent type. An Astra dispatch's receipt records role `null`, because the ciphertext cannot say whether it is review or ideation. The coordinator must read the actual brief before dispatch and enforce role/scope procedurally. Receipts mark brief checks unavailable on this path and record `header: null`, and the dispatch gets no router decision (the `task_name` join is not built). Plaintext paths record the validated routing header (never the brief body); receipts are request evidence, not semantic validation or proof of effective child model.

Plaintext Codex dispatches get the same `route` row, modes, `TW-Override:` rule, and error handling as Claude (see [Claude routing](claude.md)), with two differences: `active` behaves as `advisory` (the denial names `reasoning_effort=<tier>`), and there are no `race` or `cost` rows. `tw.py outcome`, `route`, and `promote` take `--harness codex`; `outcome` runs a brief's `TW-Check` in the hook envelope's `cwd` as on Claude, under bash with `-eo pipefail` (Git for Windows' bash on Windows; a shell that is not GNU bash gives `unknown`, `no pipefail shell`) (see `SKILL.md`; no `cwd` in the envelope gives `unknown`, `cwd missing`), and refuses (exit 2, nothing written) a dispatch denied by the guard or advised by the router. Since the check runs in that recorded `cwd`, write it to `cd` into the repository by absolute path first, e.g. `TW-Check: cd /c/Users/Arian/Code/skills && python thinker-worker/scripts/test_tw_check.py`. `promote` prints one verdict per (class, model) and takes `--model`; the model is the executed one from a `cost` row, and native Codex dispatches have none, so every Codex dispatch that would enter an arm is counted in `n_excluded_identity` and both arms stay empty. The ticket hashes the explicit `model` with the `message`, so a cached decision holds only for the same model. A `TW-Pin: user <what was asked>` line in lines 2–12 (an explicit user model/effort request) stops the router from advising or exploring that dispatch and marks its row `pinned: true`. Decision-model backends, the margin gate, exploration around the final pick, and the route row's `backends`, `combined`, `combined_mean` and `gate` are as on Claude. As shipped every class is `advisory` with no backend and the decaying schedule `explore: {"c": 0.5, "power": 0.25, "floor": 0.05}`, on Codex as on Claude (`router.classes` is not per harness; the class count `t` is per harness): a plaintext dispatch above the role's cheapest `reasoning_effort` is advised one tier down with probability ε_t = max(0.05, min(1, 0.5 / t^0.25)) at the class's t-th routed dispatch, after the per-flag `router.risk_floor` (as shipped all `medium`).

**Exploration protocol.**
1. A denial saying `router picks <tier> (exploration); dispatch reasoning_effort=<tier>` means: re-dispatch the **same `message` unchanged** with that `reasoning_effort` (same model, same `fork_turns`). The same ticket reuses the cached decision, so it is admitted.
2. Judge the result as usual. Rejected because the tier was too low → `tw.py outcome --harness codex … --accepted no --cause tier`, then re-dispatch the same `message` unchanged at your original `reasoning_effort` (admitted: cached, no re-exploration). Rejected for another reason → `--cause brief` or `--cause other`.
3. If the brief must change before a re-dispatch (at the explored `reasoning_effort` or back at yours), add `TW-Override: exploration re-dispatch, brief changed` in lines 2–12. A changed brief is a new ticket, so without `TW-Override` a re-dispatch at t−1 can itself be explored down to t−2, and one at t can be explored again.
4. Keep your `reasoning_effort` with `TW-Override: <reason>` only where exploration is unsafe for a reason the risk flags do not capture; an overridden dispatch the router would have explored shows on its route row as `eligible: true` with `action: null` (receipts never hold the override text).

Official contract: [Codex hooks](https://learn.chatgpt.com/docs/hooks), [subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents).
