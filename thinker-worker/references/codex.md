# Codex routing

Use an explicit native `spawn_agent` model and reasoning effort. Primary worker: `gpt-6-sol` or `gpt-5.6-sol`, with supported `low`, `medium`, `high`, `xhigh`, `max`, or `ultra` effort as the selected model permits. A deliberate independent-review exception uses `gpt-6-astra` with `TW-Role: independent-review` and a bounded authorization in the brief; activate `--review` first. Optional `gpt-6-luna` is only a short, objectively checkable leaf with `TW-Role: leaf`, activated by `--luna`; start with low effort. Prefer a deterministic command for exact extraction when it suffices. No Luna physics judgment, architecture, adversarial review, or acceptance.

Pass `fork_turns: "none"` or a bounded positive history count whenever using explicit model/effort. Omitted or `all` is rejected while this mode is active. The model/effort override requires `fork_turns` other than full history in the current desktop tool. Keep `message` first line as the role declaration; put the assignment below it. A manual model/effort pin takes precedence over this mode: report incompatibility instead of silently changing it or deactivating the mode.

Activation is exact-session only. Resolve the absolute installed skill directory from the Codex skill catalog, and use its `scripts/tw.py` with the actual `CODEX_THREAD_ID` for this task. The command is `python "<skill-dir>/scripts/tw.py" activate --harness codex --session "<actual CODEX_THREAD_ID>"`; replace the session placeholder with the task's real ID. `status` reports requested activation; it cannot establish trust or interception. Inspect `/hooks` to review and trust the exact owned hook definition. A changed definition needs renewed trust. Record a live hook receipt and the first actual child turn's model/effort metadata separately. A CLI hook result does not qualify an already-running desktop task; probe that surface independently. New/forked session IDs start inactive. Same-session resume retains activation until `deactivate`.

When the owned PreToolUse hook is loaded and trusted, its matcher covers legacy `spawn_agent`/`Agent` and the MultiAgentV2 hook name `collaborationspawn_agent`. The latter is the flattened hook payload name; the displayed `collaboration.spawn_agent` tool notation is not the matcher string. The guard covers fresh calls only where Codex invokes PreToolUse. It does not cover continuation via `followup_task`, cross-task messages, arbitrary shell/provider calls, or provider substitutions. Before resuming a child, verify its effective model/effort and assignment from runtime metadata; do not rely on a continuation prompt. A direct script invocation or hook listing alone does not prove live interception. An allowed guard result has no permission override.

On MultiAgentV2, Codex presents the `message` to PreToolUse as ciphertext. The hook cannot inspect its role declaration, review authorization, scope, or task content. For `collaborationspawn_agent`, it derives route from the visible explicit model (`Sol` worker, `Astra` review, `Luna` leaf), and checks model, effort, fork mode, agent type, and the exact-session review/Luna flags. The coordinator must read the actual brief before dispatch and enforce role/scope procedurally. Receipts mark brief checks unavailable on this path; they are request evidence, not semantic validation or proof of effective child model. Plaintext legacy Codex and Claude paths keep their brief checks.

Official contract: [Codex hooks](https://learn.chatgpt.com/docs/hooks), [subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents).
