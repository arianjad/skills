# Claude Code routing

For Opus 5.5 independent review, use the supported wrapper with full model ID `claude-opus-5-5`; it selects the generated pinned `-opus55` agent without a per-call alias override and verifies returned model/effort evidence. Generic `opus` is not an independent-review route. Direct native dispatch bypasses wrapper definition checks and is not the supported pinned path.

The installer generates one agent per role and tier from `routes.json` (`harnesses.claude.roles`): `~/.claude/agents/tw-<role>-<tier>.md`, with `model:` the role's first listed model and `effort: <tier>`. `tw.py models --harness claude` lists each role's models, tiers, priors, default and dispatch path. The Codex models in a role's list (`via: tw.py codex`) run through `tw.py codex --model <m>` (the Codex pipeline in `SKILL.md`), not `Agent`; that command admits a model only if some Codex role in `routes.json` lists it too, and a native `Agent` call naming such a model is denied (`model <m> is a Codex model; dispatch it with `tw.py codex --model <m>``). Invoke native `Agent` with `subagent_type: tw-<role>-<tier>`, the role matching the brief's `TW-Role:` line: the tier is the effort. Dispatch `tw-<role>-<tier>` with no `model` argument for the role's first model (the agent file's pin); any other native model in the role's list is a per-call `model` alias, within its `tiers`. A role's optional `model_tiers` (`{model: [tiers]}`, each a subset of the role's tiers; every tier list, the role's included, must be non-empty, unique and in ascending order, since the router steps by position) narrows the tiers for that model: the guard denies a tier outside it (`tier <t> is outside <role>'s tiers [...] on <model>`), and the router's ladder, exploration, cached decisions and `prior_tier` use it, so a model limited to `high`/`xhigh` is never advised or rewritten below `high`; a cached decision whose tier is clamped into the ladder is recorded with confidence 0 and probs on that tier alone. Choose the worker model per assignment using `SKILL.md`'s worker selection policy and pass its native alias explicitly. For other roles, `router.defaults` is default guidance (see `SKILL.md`); the agent file remains a compatibility pin. The effort router does not select the model. A per-call `model` outside the role's `models` list is denied (`model <m> is not allowed for <role>`). A per-call model takes precedence over the agent file, so check the effective child model/effort in `/tasks` or supported runtime turn metadata; a request accepted by the guard is not that evidence.

A Sonnet or Luna leaf is for a short, objectively checkable task at low, medium or high effort; prefer a deterministic command for exact extraction when sufficient. Start with low or medium; high allows more reasoning within the same bounded scope. Do not assign it physics judgment, architecture, adversarial review, or acceptance. Keep work that may need to stop and escalate (physics conventions, ambiguous acceptance) on a worker.

Use the activation command in the rendered `SKILL.md`; that is where Claude substitutes the exact `${CLAUDE_SESSION_ID}` and `${CLAUDE_SKILL_DIR}` values. Do not activate on cwd alone. The skill may be discovered during an existing session, but installed settings hooks or agent definitions may require a new session. `status` reports the activation record, not hook loading or effective routing; `activate` and `status` both end with the effective tier priors line (`Tier priors (installed routes.json[ + <override path>]): *=medium, …; risk floors: …`, or `override ignored: <reason>` as the source). Pick the tier from the priors `activate` prints for the brief's `TW-Class`; deviate by judgment when the brief is clearly easier or harder than its class; physics or convention judgment never below `medium`; `high` or `xhigh` for adversarial reasoning. The priors are `routes.json` `router.priors` merged with the user override file (`TW_ROUTES_OVERRIDE`, else `~/.thinker-worker/routes.json`; only `router.priors`, `router.model_priors` (each model's table over its installed one), `router.classes` (each entry over `*`), `router.risk_floor`, `router.defaults`, and the decision-model keys: `router.backends` (a list; replaces), `router.combine`, `router.options` and per-backend `kind: "jev"` blocks (merged key by key); not installer-owned; ignored when `TW_ROUTES` pins the routes). An override that fails to parse or validate is ignored (fail open) and logged per dispatch; the installed file still fails closed. After a dispatch the router takes no action on, at a tier other than its prior, the hook returns only `additionalContext`: `thinker-worker: prior for <class> is <prior>; you dispatched <tier> (fine if deliberate)`. New session IDs start inactive; same-session resume stays active until `deactivate`.

The PreToolUse hook covers fresh native `Agent` calls only. It denies fork requests made through `Agent` (`fork`/`fork_context`) and resume fields, and a brief whose optional `TW-Output: <path>` has a basename matching `REFUSED_OUTPUT` in `tw.py` (`(?i)(report|summary|findings|analysis).*\.md`, which Claude Code refuses to a native subagent's Write; probed 2026-09-28 on 15 names, anthropics/claude-code#44657; the `tw.py codex` pipeline's own call is exempt), and does not cover `SendMessage` continuation, forks started any other way, arbitrary shell/provider paths, or model substitution by provider policy. Before continuing a child, verify its existing model/effort, role, and assignment. Everything up to admission fails closed (any guard error denies); the hook leaves ordinary permission checks intact on accepted calls. A user-pinned model or effort that conflicts with this mode must be surfaced, not overwritten.

**Routing.** After admission the hook (and `tw.py codex`, through the same code; its modes are in the `SKILL.md` Codex pipeline) computes a router decision and appends a `route` receipt row; a failure from here on writes a `kind: "error"` row (`where: "route"`) and the admit stands. Decision models decide and you are the fallback (design D14). Every backend named in `router.backends` is asked in parallel, one thread each, within `router.budget_s`: a name in `tw.py` `BACKENDS` (`table`), or a `router.<name>` block with `kind: "jev"` (`url` of a Jev/TypeSafe `POST /v1/systemone` server such as `kev.serve`; `body_chars`, default 1500, of brief body sent after the `TW-Role` and routing header lines; the option wording is `router.options`, provisional, overridable per block). An answer is invalid unless every probability it gives is a finite number in [0, 1] (a boolean or a score is never coerced); a response body over 64 KiB (`JEV_MAX_BYTES`) is an error (`oversize`) before it is parsed, so a huge body cannot hold the router past its budget. The valid answers, renormalized over the role's tiers (intentionally: mass on a tier outside the role is dropped), are combined by a weighted geometric mean, p(t) ∝ Π pᵢ(t)^wᵢ (wᵢ = `router.combine.weights[<name>]`, else 1/n; a zero floored at 1e-6), and the combined pick acts (`source: bayes`, confidence its combined probability) only if its top-1 minus top-2 probability is at least `router.combine.margin` (as shipped 0.2); otherwise, or with no valid answer (exception, overrun, invalid answer), your tier stands (`source: coordinator`). Then a ticket whose coin (`int(ticket, 16) / 16**12`) falls below the class's ε at this dispatch goes one tier below that final pick, the models' or yours (`source: explore`, confidence 0; never below the role's cheapest tier). As shipped `router.backends` is empty (the `kev` and `laya` blocks are inert until listed; enable one with the user override, e.g. `{"router": {"backends": ["kev"], "classes": {"*": {"mode": "active"}}}}`, which lists the backend and runs every class `active` with its `explore` kept: decision models rewrite a dispatch only in `active` (in `advisory` a gated pick only denies with advice, in `shadow` it is only logged), and the competing-writer guard can still hold a Claude class advisory) and every class is `advisory` with `explore: {"c": 0.5, "power": 0.25, "floor": 0.05}`, a decaying schedule: at a class's t-th routed dispatch (t = 1 + its earlier non-pinned route rows across all receipt files) the exploration probability is ε_t = max(floor, min(1, c / t^power)), so 0.5 at first, 0.25 at t = 16, never below 0.05 (SLARouter's forced exploration, arXiv 2606.19376; a plain number is a constant ε); so a class's early dispatches above the role's cheapest tier are advised one tier down about half the time, falling toward 5 %, and the rest run at your tier; `router.table` and the backend blocks stay in the file, inert while no backend is listed. The mode per `TW-Class` comes from `router.classes` (`*` is the default): `shadow` logs; `advisory` denies with the router's pick and the hint to redispatch that agent or add `TW-Override: <reason>`; `active` allows the call with `subagent_type` rewritten to the pick (`updatedInput`). In `active`, the rewrite reaches the coordinator only as the hook's `additionalContext` line (`thinker-worker: dispatched as <router agent> instead of <requested agent> (router p=<confidence>); judge the result at that tier`); the child's real agent is its `meta.json` `agentType`, and the route row has `action: "rewrite"` and `router_agent`. Either action needs a router pick different from your tier: a gated `bayes` pick at any confidence, or an explored one. The router's pick is first raised to the highest `router.risk_floor` among the brief's `TW-Risk` flags (as shipped, `physics`, `destructive` and `external` all → `medium`); a pick raised to your tier or above takes no action and its row is `eligible: false`. The floor lifts only the router's pick: a dispatch of yours below a flag's floor is not advised up (physics never below `medium` is your rule, in `SKILL.md`). A non-empty `TW-Override:` line in brief lines 2–12 keeps your tier. The ticket is a hash of the brief without its `TW-Route:` lines (a line the coordinator adds from `tw.py route` output, the phase-2 Codex v2 carrier) and `TW-Override:` lines; it does not include the model (design D17), so a re-dispatch of the same brief in the session, on any model, reuses the first bayes or exploration decision (`source: cached:bayes`, which advises again at another tier, or `cached:explore`, which does not; never re-explored, no backend asked), while coordinator decisions are recomputed.

**Decision servers.** The shipped `kev` and `laya` blocks point at local CPU servers on `127.0.0.1:8766` and `:8767`, run from the source repo (`servers/` is not installed): `python ~/Code/skills_public/thinker-worker/servers/decision_servers.py start|stop|status` (`start` is idempotent; `--selftest` checks it). Their venv paths are Windows-only as written. A listed backend whose server is down fails its call, so its answer is invalid and, with no other valid answer, your tier stands (`source: coordinator`). On Windows a connect to a closed localhost port is refused only after about 2 s (measured 2026-09-28), so the connect has its own bound, `JEV_CONNECT_S` (0.5 s, about 20× the worst live connect measured under load), and the reply keeps the budget left: a down server costs a dispatch about 0.5 s (`error: "URLError: <urlopen error timed out>"`), not the whole `router.budget_s`. On the Windows machine a Startup-folder script, `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\thinker-worker-decision-servers.cmd`, runs `start` at logon and logs to `~/.thinker-worker/autostart.log`; it is machine-local, not written by `tw.py install` (a `schtasks /SC ONLOGON` task needs an elevated shell).

**Exploration protocol.**
1. A denial saying `router picks <tier> (exploration)` means: re-dispatch the **same brief unchanged** at that agent. The same ticket reuses the cached decision, so it is admitted.
2. Judge the result as usual. Rejected because the tier was too low → `tw.py outcome … --accepted no --cause tier`, then re-dispatch the same brief unchanged at your original tier (admitted: cached, no re-exploration). Rejected for another reason → `--cause brief` or `--cause other`.
3. If the brief must change before a re-dispatch (at the explored tier or back at yours), add `TW-Override: exploration re-dispatch, brief changed` in lines 2–12. A changed brief is a new ticket, so without `TW-Override` a re-dispatch at t−1 can itself be explored down to t−2, and one at t can be explored again.
4. Keep your tier with `TW-Override: <reason>` only where exploration is unsafe for a reason the risk flags do not capture; an overridden dispatch the router would have explored shows on its route row as `eligible: true` with `action: null` (receipts never hold the override text).

**context-mode.** The home heal (`~/.claude/hooks/plugin-patch-heal.mjs`) removes context-mode's PreToolUse `Agent` hook at SessionStart, and a SubagentStart nudge replaces its prompt block (decision and rationale: `~/obsidian-vault/03-decisions/2026-09-26-effort-routing-single-writer-router-context-mode-coexistence.md`). The guard in `tw.py` (`competing_agent_writer`) still holds an `active` class to advisory, with `[active held: <reason>]` on the denial, whenever context-mode is not explicitly disabled and a PreToolUse matcher of its matches `Agent` (Claude Code matcher rules, legacy `Task` included), its `hooks.json` changed after this Claude process started (or that start is unknown), its state cannot be read, or a race was lost earlier in the session.

**Receipts** (`~/.thinker-worker/receipts/claude/<sha256(session)>.jsonl`) never hold the brief body; header values are cut at 256 characters.
- `dispatch`: the gate's `admit` or `deny`, with `check` (the brief's full `TW-Check`, not cut, else null) and `cwd` (the hook envelope's, or `tw.py codex --cd`). A router-advised denial still shows `admit` here and `action: "advise"` on its `route` row, so count dispatches that ran by joining on the route row's `action`, never by `admit` alone.
- `error` with `where: "override"`: the user override file was ignored; `error` says why (one row per dispatch while it stays bad).
- `route`: `coordinator_tier`, `router_tier`, `prior_tier` (the class prior clamped to the role), `source`, `mode`, `action` (`null`, `advise`, `rewrite`), `guard`, `eligible` (the router's pick, gated bayes or explored, differs from your tier and no risk floor lifted a lower pick to it, so the router would act in any mode; `null` if the action step failed), `explore` (the class's `explore` as configured: a number or the schedule), `eps` (the ε used at this dispatch; 0 on a cached or pinned row), `propensity` (the probability of the executed action: the exploration draw has two branches, explored with probability ε and not explored with 1 − ε, and `propensity` sums the branches whose action after the risk floor, `TW-Override`, pin and mode is this row's, the same `action` naming the same tier (with no action, your tier runs); so a floor that sends both branches to the same rewrite gives 1.0, and shadow or overridden rows are 1.0; 1.0 with no draw (ε = 0, cached, pinned, nothing below the final pick); `null` if the action step failed), `draw_propensity` (the probability of the drawn branch before that mapping: `eps` on an explored row, 1 − `eps` on a row that was eligible for exploration (ε > 0 and a tier below the final pick) but not explored, else 1.0), `target_tier` (the pick after the risk floor; `router_tier` stays the raw pick), `router_agent` (names `target_tier`), `agent_model` (the per-call model, else the role's first listed model), `quota` (both plan meters as last read locally, raw, design D19/D20: `claude` = the last line of `~/.claude/usage-meter.jsonl`, written by the status line when its 5h/7d percentages change, as `{at, five_hour, seven_day}`; `codex` = the newest `~/.codex/sessions` rollout line whose `rate_limits.limit_id` is `codex`, as `{at, primary, secondary}`; either is null when missing or unreadable, and `at` shows how stale it is), `via` (`codex-exec` on a `tw.py codex` dispatch, else absent), `pinned` (a non-empty `TW-Pin:` line in brief lines 2–12: never advised, rewritten, or explored, no prior reminder; `promote` skips the row), `ticket`, `provenance`, `backends` (every configured backend: `{tier, probs, ms, body_chars_sent}`, or `{error, ms, body_chars_sent: null}` with `error: "timeout"` and no `ms` past the budget; a failed call's send is unknown, never 0; `{}` on a cached row), `body_chars_sent` (the most brief-body characters sent to any backend, whether or not the gate passed; null if every backend call failed, 0 with no backend or on a cached row), `combined` (the geometric-mean probabilities, logged whether or not the gate passed), `combined_mean` (their arithmetic mean, logged only, so other pooling rules can be scored offline) and `gate` (`pass`, `margin`, or null with no valid answer).
- `race`: at each dispatch and at `outcome`, every unchecked rewrite whose child has spawned is checked. The child's `meta.json` `agentType` must equal `router_agent`; only when `agentType` is absent, its first prompt must not carry context-mode's block. A loss sets the session advisory. A failed check writes `race-error`. A `tw.py codex` rewrite is checked once, right after the run: `lost` unless the rollout's effective effort equals `target_tier` (`via: "codex-exec"`, `effective_effort`); it never sets the session advisory.
- `outcome` and `cost`: `tw.py outcome` labels the dispatch (the last label wins; `cause` is `tier`, `brief` or `other` from `--cause`, allowed only with `--accepted no`, else null; a dispatch that never ran, its `dispatch` row `deny`, its `route` row `advise`, or a `tw.py codex` dispatch without a `cost` row, exits 2 with nothing written) and, once the child transcript exists, writes one `cost` row from it (token sums over the last usage row per `message.id`; `model` is the last non-`<synthetic>` assistant `message.model`, the model that ran, else null; `effort` is the transcript's last assistant `effort`, the effort that ran, present only when the transcript has it (never back-filled from `meta.json`, whose `model`, if any, is recorded as `requested_model`: the request, not evidence); `advisor_calls` and `advisor_available` show a Fable advisor consult or offer), or `cost-error`.
- `check`: `tw.py outcome` runs the dispatch's `TW-Check` once (unless `--no-check`; `--accepted` is optional when there is one) in its `cwd` as `<shell> --noprofile --norc -eo pipefail -c <check>` (GitHub Actions' `shell: bash`): `TW_CHECK_BASH` if set, else on Windows the bash of git's own install (`git --exec-path`, walked up to `usr/bin/bash.exe` or `bin/bash.exe`; never a PATH bash or cmd.exe), else `bash` (else `sh`) on PATH; a shell whose `--version` does not start `GNU bash` is never run, since without pipefail `failing | cat` exits 0 (Git's `sh.exe` and macOS `/bin/sh` are bash). It records `label` `pass` (exit 0), `fail` (nonzero) or `unknown` (`unknown_reason`: `timeout` after `--check-timeout`, default 900 s, when the process tree is killed; `cwd missing`; `no git bash`; `no pipefail shell`; `TW_CHECK_BASH not a file: …`; `launch error: …`), `exit_code`, `seconds`, `tail` (the last 400 characters of stdout + stderr), `shell` (the resolved path; null with `cwd missing`, when no shell is resolved), `shell_version` (first line of `--version`, else null) and `kill_failed` (after a timeout, true when `taskkill` failed or overran, or the process had not exited, within a 10 s cleanup budget that `taskkill` and the exit wait share, so the tree may still run; the `tw.py codex` cost row has the same field for `TW_CODEX_TIMEOUT`). The check runs in the dispatch's recorded `cwd`, so write it to `cd` into the repository by absolute path first, e.g. `TW-Check: cd /c/Users/Arian/Code/skills_public && python thinker-worker/scripts/test_tw_check.py`.

`tw.py route --harness claude --role <r> --brief-file <f> [--model <m>]` prints the decision for a brief at its `TW-Class` prior (clamped to the model's tiers; `--model` defaults to the role's first model) and writes no receipt: `tier`, `probs`, `confidence`, `source`, `ticket`, `mode`, and why, with `backends`, `combined`, `gate` and `eps` as on a `route` row. `tw.py promote --harness claude [--class <c>] [--model <m>]` reads every receipt file and prints one JSON verdict line per (class, model) group, each naming its `class` and `model` (the executed model: the dispatch's latest `cost` row `model`, else null; never the requested `agent_model` or a role default): the router arm is labeled, race-verified lower-tier rewrites plus re-dispatches that took an advised lower tier; the coordinator arm is labeled `eligible` dispatches the router wanted lower that ran at the coordinator tier. With Beta posteriors, `promote` if P(router − coordinator ≥ −0.15) > 0.8, `demote` if < 0.2, else `hold` (defaults of `promote()` in `tw.py`). A dispatch whose cost row shows advisor calls leaves both arms (`n_advisor_excluded`). A dispatch enters an arm only on executed evidence that agrees with it: a `cost` row naming the model and positive effort evidence (a `tw.py codex` `effort`, else the tier of a `tw-*` `agent_type`) equal to the arm's tier (the floored target for a rewrite, the coordinator's tier otherwise); any other would-be arm dispatch, one with missing or unknown effort included, is counted in `n_excluded_identity`. A dispatch's label is its latest `check` row (`pass` accepted, `fail` rejected, `unknown` leaves both arms), else your `--accepted`; each verdict counts the sources as `n_check` and `n_coordinator`. Under advisory exploration the coordinator arm holds only explored dispatches kept with `TW-Override`, a selected sample, so read `promote`'s counts, not its verdict, until the phase-2 control arm lands.

Promotion evidence is joined by receipt-file session and tool-use ID, including legacy rows without session metadata. A retry counts as complying with advice only when matching advice precedes it in that session's receipt file; another session's advice or a later row cannot reclassify earlier work.
