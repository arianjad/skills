# Claude Code routing

For the configured OMP worker, use the [caller-independent OMP execution backend](omp.md). Its model selection and saved worker session belong to OMP; the native Claude routing and activation rules below apply to native children, not to the explicit OMP command.

For Opus 5.5 independent review, use the supported wrapper with full model ID `claude-opus-5-5`; it selects the generated pinned `-opus55` agent without a per-call alias override and verifies returned model/effort evidence. Generic `opus` is not an independent-review route. Direct native dispatch bypasses wrapper definition checks and is not the supported pinned path.

The installer generates one agent per role and tier from `routes.json` (`harnesses.claude.roles`): `~/.claude/agents/tw-<role>-<tier>.md`, with `model:` the role's first listed model and `effort: <tier>`. `tw.py models --harness claude` lists each role's models, tiers, priors, default and dispatch path. The Codex models in a role's list (`via: tw.py codex`) run through `tw.py codex --model <m>` (the Codex pipeline in `SKILL.md`), not `Agent`; that command admits a model only if some Codex role in `routes.json` lists it too, and a native `Agent` call naming such a model is denied (`model <m> is a Codex model; dispatch it with `tw.py codex --model <m>``). Invoke native `Agent` with `subagent_type: tw-<role>-<tier>`, the role matching the brief's `TW-Role:` line: the tier is the effort. Dispatch `tw-<role>-<tier>` with no `model` argument for the role's first model (the agent file's pin); any other native model in the role's list is a per-call `model` alias, within its `tiers`. A role's optional `model_tiers` (`{model: [tiers]}`, each a subset of the role's tiers; every tier list, the role's included, must be non-empty, unique and in ascending order) narrows the tiers for that model: the guard denies a tier outside it (`tier <t> is outside <role>'s tiers [...] on <model>`), and the prior is clamped into it. Choose the worker model per assignment using `SKILL.md`'s worker selection policy and pass its native alias explicitly. For other roles, `router.defaults` is default guidance (see `SKILL.md`); the agent file remains a compatibility pin. A per-call `model` outside the role's `models` list is denied (`model <m> is not allowed for <role>`). A per-call model takes precedence over the agent file, so check the effective child model/effort in `/tasks` or supported runtime turn metadata; a request accepted by the guard is not that evidence.

A Sonnet or Luna leaf is for a short, objectively checkable task at low, medium or high effort; prefer a deterministic command for exact extraction when sufficient. Start with low or medium; high allows more reasoning within the same bounded scope. Do not assign it physics judgment, architecture, adversarial review, or acceptance. Keep work that may need to stop and escalate (physics conventions, ambiguous acceptance) on a worker.

Use the activation command in the rendered `SKILL.md`; that is where Claude substitutes the exact `${CLAUDE_SESSION_ID}` and `${CLAUDE_SKILL_DIR}` values. Do not activate on cwd alone. The skill may be discovered during an existing session, but installed settings hooks or agent definitions may require a new session. `status` reports the activation record, not hook loading or effective routing; `activate` and `status` both end with the effective tier priors line (`Tier priors (installed routes.json[ + <override path>]): *=medium, …`, plus `; ignored override keys: …` when it names retired keys, or `override ignored: <reason>` as the source). Pick the tier from the priors `activate` prints for the brief's `TW-Class`; deviate by judgment when the brief is clearly easier or harder than its class; physics or convention judgment never below `medium`; `high` or `xhigh` for adversarial reasoning. The priors are `routes.json` `router.priors` merged with the user override file (`TW_ROUTES_OVERRIDE`, else `~/.thinker-worker/routes.json`; only `router.priors`, `router.model_priors` (each model's table over its installed one) and `router.defaults`, merged key by key; any other key, such as a setting of the removed router, is ignored and named; not installer-owned; ignored when `TW_ROUTES` pins the routes). An override that fails to parse or validate is ignored (fail open) and logged per dispatch; the installed file still fails closed. After admitting a dispatch at a tier other than its prior (and without `TW-Pin:`), the hook returns only `additionalContext`: `thinker-worker: prior for <class> is <prior>; you dispatched <tier> (fine if deliberate)`. New session IDs start inactive; same-session resume stays active until `deactivate`.

The PreToolUse hook covers fresh native `Agent` calls only. It denies fork requests made through `Agent` (`fork`/`fork_context`) and resume fields, and a brief whose optional `TW-Output: <path>` has a basename matching `REFUSED_OUTPUT` in `tw.py` (`(?i)(report|summary|findings|analysis).*\.md`, which Claude Code refuses to a native subagent's Write; probed 2026-09-28 on 15 names, anthropics/claude-code#44657; the `tw.py codex` pipeline's own call is exempt), and does not cover `SendMessage` continuation, forks started any other way, arbitrary shell/provider paths, or model substitution by provider policy. Before continuing a child, verify its existing model/effort, role, and assignment. Everything up to admission fails closed (any guard error denies); the hook leaves ordinary permission checks intact on accepted calls. A user-pinned model or effort that conflicts with this mode must be surfaced, not overwritten.

**context-mode.** The home heal (`~/.claude/hooks/plugin-patch-heal.mjs`) removes context-mode's PreToolUse `Agent` hook at SessionStart, and a SubagentStart nudge replaces its prompt block (decision and rationale: `~/obsidian-vault/03-decisions/2026-09-26-effort-routing-single-writer-router-context-mode-coexistence.md`).

**Receipts** (`~/.thinker-worker/receipts/claude/<sha256(session)>.jsonl`) never hold the brief body; header values are cut at 256 characters.
- `dispatch`: the gate's `admit` or `deny`, with `check` (the brief's full `TW-Check`, not cut, else null) and `cwd` (the hook envelope's, or `tw.py codex --cd`). Receipts written before 2026-11-02 also hold `route` and `race` rows from the removed tier router; readers ignore them.
- `error` with `where: "override"`: the user override file was ignored; `error` says why (one row per dispatch while it stays bad).
- `outcome` and `cost`: `tw.py outcome` labels the dispatch (the last label wins; `cause` is `tier`, `brief` or `other` from `--cause`, allowed only with `--accepted no`, else null; a dispatch that never ran, its `dispatch` row `deny`, or a `tw.py codex` dispatch without a `cost` row, exits 2 with nothing written) and, once the child transcript exists, writes one `cost` row from it (token sums over the last usage row per `message.id`; `model` is the last non-`<synthetic>` assistant `message.model`, the model that ran, else null; `effort` is the transcript's last assistant `effort`, the effort that ran, present only when the transcript has it (never back-filled from `meta.json`, whose `model`, if any, is recorded as `requested_model`: the request, not evidence); `advisor_calls` and `advisor_available` show a Fable advisor consult or offer), or `cost-error`.
- `check`: `tw.py outcome` runs the dispatch's `TW-Check` once (unless `--no-check`; `--accepted` is optional when there is one) in its `cwd` as `<shell> --noprofile --norc -eo pipefail -c <check>` (GitHub Actions' `shell: bash`): `TW_CHECK_BASH` if set, else on Windows the bash of git's own install (`git --exec-path`, walked up to `usr/bin/bash.exe` or `bin/bash.exe`; never a PATH bash or cmd.exe), else `bash` (else `sh`) on PATH; a shell whose `--version` does not start `GNU bash` is never run, since without pipefail `failing | cat` exits 0 (Git's `sh.exe` and macOS `/bin/sh` are bash). It records `label` `pass` (exit 0), `fail` (nonzero) or `unknown` (`unknown_reason`: `timeout` after `--check-timeout`, default 900 s, when the process tree is killed; `cwd missing`; `no git bash`; `no pipefail shell`; `TW_CHECK_BASH not a file: …`; `launch error: …`), `exit_code`, `seconds`, `tail` (the last 400 characters of stdout + stderr), `shell` (the resolved path; null with `cwd missing`, when no shell is resolved), `shell_version` (first line of `--version`, else null) and `kill_failed` (after a timeout, true when `taskkill` failed or overran, or the process had not exited, within a 10 s cleanup budget that `taskkill` and the exit wait share, so the tree may still run; the `tw.py codex` cost row has the same field for `TW_CODEX_TIMEOUT`). The check runs in the dispatch's recorded `cwd`, so write it to `cd` into the repository by absolute path first, e.g. `TW-Check: cd /c/Users/Arian/Code/skills_public && python thinker-worker/scripts/test_tw_check.py`.

`tw.py tally --harness claude` reads every receipt file and prints one JSON line per (class, executed model, executed tier): `n`, `accepted`, `rate`. A dispatch counts once it is admitted, has a routing header and a label (its latest `check` row, `pass` or `fail`, else your latest `--accepted`); the model and tier are the `cost` row's `model` and `effort`, else the tier of its `tw-*` `agent_type`, else the requested tier with model null, so historical router rewrites count at the tier that ran.
