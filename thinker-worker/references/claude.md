# Claude Code routing

Use the installed `thinker-worker-opus` agent for primary work, `thinker-worker-fable-review` only for an authorized independent review, and `thinker-worker-dreamer` only for authorized ideation (`--ideation`). Both run on `fable`; ideation may use `opus` only when the brief carries `TW-Opus-Reason: user-request` or `TW-Opus-Reason: fable-exhausted`. Neither agent pins effort, so both inherit the coordinator session's effort. For an opted-in, short, objectively checkable leaf task, use `thinker-worker-sonnet` with `TW-Role: leaf`; activate this exact Claude session with `--sonnet` first. This is the Claude counterpart to the optional Codex Luna leaf, not a Claude-to-Luna route. Sonnet is not a primary worker or reviewer in this mode. Prefer a deterministic command for exact extraction when sufficient; do not assign Sonnet physics judgment, architecture, adversarial review, or acceptance. Worker and leaf roles may instead use an `effortmining:miner-<tier>` agent (namespaced form only) to pin reasoning effort, with the same explicit model rules. Miner prompts forbid questions and meta-commentary and carry none of this mode's worker contract, so a brief to a miner must restate it: no child dispatch, checkpoint to the named file, preserve others' edits, and report uncertainty and unverified claims explicitly. Keep work that may need to stop and escalate (physics conventions, ambiguous acceptance) on `thinker-worker-opus`.

Invoke native `Agent` with the actual owned `subagent_type`, an explicit `model` (`opus`/supported exact Opus ID, `fable`/supported exact Fable ID, or `sonnet`/`claude-sonnet-5` for the leaf), and `prompt` beginning with the role declaration. The Opus/Fable definitions set effort `high`; Sonnet sets `low`. No per-call Agent effort field is assumed. A per-invocation model takes precedence over the definition, so check the effective child model/effort in `/tasks` or supported runtime turn metadata. A request accepted by the guard is not that evidence.

Use the activation command in the rendered `SKILL.md`; that is where Claude substitutes the exact `${CLAUDE_SESSION_ID}` and `${CLAUDE_SKILL_DIR}` values. Do not activate on cwd alone. The skill may be discovered during an existing session, but installed settings hooks or agent definitions may require a new session. `status` reports the activation record, not hook loading or effective routing. New session IDs start inactive; same-session resume stays active until `deactivate`.

The PreToolUse hook covers fresh native `Agent` calls only. It denies fork requests made through `Agent` (`fork`/`fork_context`), and does not cover `SendMessage` continuation, forks started any other way, arbitrary shell/provider paths, or model substitution by provider policy. Before continuing a child, verify its existing model/effort, role, and assignment. The hook leaves ordinary permission checks intact on accepted calls. A review exception requires `--review` activation and an authorization cited in the brief; a Sonnet leaf requires the separate `--sonnet` flag. Old activation records without a Sonnet field remain disabled for Sonnet. A user-pinned model or effort that conflicts with this mode must be surfaced, not overwritten.

Official contracts: [Claude hooks](https://code.claude.com/docs/en/hooks), [subagents](https://code.claude.com/docs/en/sub-agents), [skill session substitution](https://code.claude.com/docs/en/skills#available-string-substitutions).
